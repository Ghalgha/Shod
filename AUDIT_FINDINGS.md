# Сводный перечень ошибок и недочётов

Сводка результатов аудита ветки migration/phase-1-foundation. Подробный журнал AUDIT_TRACKER.md сохранён без изменений.

## Принцип сортировки

Записи расположены ориентировочно от простых к сложным по трудоёмкости: интерфейс и ресурсы → прикладная логика и валидация → сборка и инфраструктура → сетевой код, безопасность, конкурентность и криптография.

Статусы:
- **Подтверждённый дефект** — нарушение поведения или контракта установлено статическим анализом кода.
- **Риск / пробел контроля** — проблема зависит от условий эксплуатации либо недостаточно покрыта тестами; не приравнивается к доказанной runtime-ошибке.

## 1. Простые локальные дефекты: интерфейс, отображение и ресурсы

1. **Повреждённый PNG-ресурс — rust-server/src/web_panel/assets/pwa-icon-512.png.b64.**  
   **Подтверждённый дефект.** Объявленная длина PNG-чанка IDAT превышает оставшиеся данные файла. Структура PNG некорректна, строгие декодеры не смогут корректно прочитать иконку. Заменить ресурс корректным PNG и проверить декодирование.

2. **Неверная подпись остаточных объектов — app/src/main/java/com/shod/client/ui/screens/deploy/ServerInventoryPresentation.kt.**  
   **Подтверждённый дефект.** Любой объект LEFTOVER отображается как «Остановленная служба shod», хотя контракт допускает отдельный бинарник или хранилище. Использовать нейтральную подпись либо определять её по типу объекта.

3. **Ложное сообщение об успешном копировании — rust-server/src/web_panel/assets/group-admin.html.**  
   **Подтверждённый дефект.** Fallback в copyToClipboard() игнорирует boolean-результат document.execCommand('copy') и безусловно возвращает успех. UI может сообщить об успешном копировании, хотя браузер его не выполнил. Проверять результат операции.

4. **Повторная подстановка маркеров в имени клиента — rust-server/src/web_panel/assets/client-subscription.html.**  
   **Подтверждённый дефект.** Имя клиента вставляется в шаблон до глобальной замены __Shod_LINK__. Допустимое пользовательское имя с такой последовательностью частично заменяется ссылкой. Использовать одноразовую структурированную подстановку.

5. **Повторная подстановка маркеров в имени группы — rust-server/src/web_panel/assets/group-subscription.html.**  
   **Подтверждённый дефект.** Имя группы вставляется до последующих замен __CLIENTS_COUNT__ и __CLIENTS_JSON__; совпадающие последовательности в имени изменяются, а второй маркер может привести к вставке JSON списка клиентов в заголовок. Исключить повторную обработку пользовательских значений.

6. **Неверная классификация отрицательного сообщения DTLS — app/src/main/java/com/shod/client/vpn/diagnostics/DtlsLogParser.kt.**  
   **Подтверждённый дефект.** Поиск подстрок «успешен»/«завершено» не учитывает отрицание: сообщение «DTLS не завершено» может быть засчитано как успешное рукопожатие. Использовать однозначные шаблоны и добавить тесты отрицательных формулировок.

7. **Адрес сервера не сохраняется при выключенных ручных портах — app/src/main/java/com/shod/client/ui/screens/credentials/CredentialsScreen.kt.**  
   **Подтверждённый дефект.** В соответствующей ветке onValueChange обновляет только локальное поле и не вызывает scheduleSave(). Адрес теряется после ухода с экрана или перезапуска. Сохранять значение в обоих режимах.

8. **Неполная проверка JSON-резервной копии — app/src/main/java/com/shod/client/ui/screens/routing/apps/AppRoutingTransferDialog.kt.**  
   **Подтверждённый дефект.** Наличие объекта apps принимается за достаточный признак корректной копии; версия не проверяется, а отсутствующие/неверные массивы превращаются в пустые множества. Повреждённый документ может быть принят и привести к стиранию текущих правил. Проверять версию и типы обязательных полей до вызова импорта.

9. **Недоступная вкладка журнала — app/src/main/java/com/shod/client/ui/navigation/MainScreen.kt.**  
   **Подтверждённая проблема навигации.** В текущем наборе навигации остаётся только вкладка 0; ветка перехода к LogsScreen для вкладки 3 недостижима, а ProxyNavigationBar не подключена. Если журнал должен быть доступен, восстановить маршрут; если его намеренно убрали — удалить устаревшую ветку. Намерение скрыть журнал не подтверждено.

## 2. Прикладная логика, валидация и обработка ошибок

10. **Импорт сообщает об успехе при неудачной записи — app/src/main/java/com/shod/client/ui/dialogs/ImportExportDialog.kt.**  
    **Подтверждённый дефект.** На Android 10+ saveJsonToDownloads() возвращает успешный путь, даже если openOutputStream(uri) вернул null. UI сообщает об успешном сохранении, хотя запись не состоялась. Отсутствие потока должно считаться ошибкой. При неудачной записи также следует удалять созданную MediaStore-запись.  
    **Риск:** импорт файла читает весь поток через readText() без ограничения размера; большой JSON может вызвать чрезмерное потребление памяти/OOM.

11. **Изменение SSH passphrase при вводе — app/src/main/java/com/shod/client/ui/dialogs/SshKeysDialog.kt.**  
    **Подтверждённый дефект.** Пробелы удаляются в onValueChange, затем вызывается trim(). Passphrase является произвольной строкой, поэтому секрет изменяется и SSH-аутентификация может не пройти. Не фильтровать и не обрезать passphrase.  
    **Риск конфиденциальности:** приватный ключ и passphrase помещены в rememberSaveable и могут попасть в сохранённое состояние Activity/Compose. Секреты следует держать в несохраняемом состоянии.

12. **Неправильная проверка порта в Host — rust-server/src/web_panel.rs.**  
    **Подтверждённый дефект.** parse_host_header() проверяет только непустоту, длину и цифровой формат порта, но не диапазон u16. Значения 65536–99999 принимаются и могут попасть в HTTPS Location, формируя некорректный redirect. Проверять диапазон 1–65535 до построения URL.

13. **Ошибочная обработка результата копирования APK — scripts/build_apk.bat.**  
    **Подтверждённый дефект.** Команды copy /Y не проверяют код возврата, а наличие старого целевого APK воспринимается как успех. Скрипт может сообщить DONE и завершиться с кодом 0, хотя свежий APK не скопирован или исходный отсутствует. Проверять каждое копирование и фактический набор выходных APK с учётом ABI.

14. **Недействительный Android SDK принимается как найденный — scripts/find_android_sdk.bat.**  
    **Подтверждённый дефект.** ANDROID_HOME и ANDROID_SDK_ROOT принимаются при простом существовании пути, без проверки структуры SDK. Ошибочная переменная блокирует fallback-поиск, а скрипт сообщает об успехе. Валидировать обязательные компоненты SDK и продолжать поиск при недействительном кандидате.

15. **Недействительный Android NDK блокирует fallback-поиск — scripts/find_android_sdk_ndk.bat.**  
    **Подтверждённый дефект.** ANDROID_NDK_HOME, ANDROID_NDK_ROOT и NDK_HOME принимаются без проверки наличия toolchain. Уже заданный NDK_ROOT мешает поиску корректного NDK в SDK и стандартных каталогах. Проверять наличие NDK toolchain и продолжать fallback.

16. **Некорректные режимы routing молча превращаются в blacklist — rust-server/src/web_panel/routing.rs.**  
    **Подтверждённый дефект.** В create/update любое непустое значение mode, domains_mode и ip_mode, отличное от точной строки whitelist, превращается в false. Ошибочный ввод меняет политику вместо HTTP 400. Валидировать enum до изменения БД.

17. **Импорт конфигурации обходит DNS-валидацию — rust-server/src/web_panel/settings.rs.**  
    **Подтверждённый дефект.** api_import_post() напрямую записывает DNS-адреса и ID провайдера без проверок, применяемых обычными endpoint'ами, и может разослать невалидную DNS-конфигурацию активным туннелям. Также импорт принимает неподдерживаемые значения auto_restart_interval_hours вместо допустимых 0/12/24/48/72. Повторно использовать штатную валидацию до изменения БД.

18. **Неправильный подсчёт CPU при guest time — rust-server/src/main.rs (parse_cpu_total).**  
    **Подтверждённый дефект.** Суммируются guest и guest_nice, хотя Linux уже включает их в user и nice. Общий знаменатель завышается, загрузка процесса занижается. Исключить повторный учёт этих счётчиков.  
    **Риск:** is_public_ipv4() исключает лишь unspecified, loopback и RFC1918; CGNAT, link-local, документационные, benchmarking, multicast и reserved адреса могут быть ошибочно признаны публичными.

19. **Неправильное определение sudo-команды и возможная передача пароля постороннему процессу — app/src/main/java/com/shod/client/deploy/ssh/SshRemoteCommandExecutor.kt.**  
    **Подтверждённый дефект безопасности.** Любое вхождение подстроки sudo запускает запись sudoPassword в stdin, даже для команды вроде echo sudo. Если процесс читает stdin, пароль может быть раскрыт или обработан как обычный ввод. Глобальная замена sudo также затрагивает аргументы и quoted-текст. Распознавать команду структурно и передавать секрет только реальному sudo-процессу.

20. **Неполный контроль потерь в нагрузочных тестах — rust-client/src/transport/turn/integration_tests.rs.**  
    **Пробел тестового контроля, не подтверждённая runtime-ошибка.** Отчёт собирает client_ingress_drops, но health assertion не проверяет его; также достаточно доставить хотя бы один пакет. Тест может пройти при значительных потерях. Установить допустимый порог и проверять полноту доставки.

21. **Внешние fingerprints делают browser-тесты нестабильными — rust-client/vendor/primp/src/imp/safari/mod.rs.**  
    **Подтверждённая ошибка сборки и риск тестов.** Безусловный вызов build_http2_settings() остаётся при отключённой feature http2, хотя сама функция в этой конфигурации не компилируется; --no-default-features ломает сборку. Дополнительно шесть интеграционных тестов зависят от внешнего tls.browserleaks.com и неизменности JA4/Akamai fingerprints.

22. **Сборка Opera ломается без default features — rust-client/vendor/primp/src/imp/opera/mod.rs.**  
    **Подтверждённый дефект.** build_opera_settings() безусловно вызывает build_http2_settings(), объявленную только при feature http2. При --no-default-features crate не компилируется. Согласовать cfg вызывающей функции и вызываемой реализации.

23. **Недостаточная фиксация сторонних GitHub Actions — .github/workflows/build-android-native.yml, .github/workflows/build-linux-server.yml, .github/workflows/ci.yml.**  
    **Рекомендация по цепочке поставки, не подтверждённая ошибка.** Actions подключены по изменяемым тегам @vN, а не полным commit SHA. Для защиты от перемещения/подмены тегов фиксировать проверенные SHA и указывать версию в комментарии.

## 3. Сборка, provenance и системная инфраструктура

24. **Неполный путь в systemd ExecStart — scripts/run_wsl_checks.sh.**  
    **Подтверждённый дефект.** ExecStart записывает путь к бинарнику и WORK_DIR/systemd без корректного systemd-экранирования. Пробелы в пути (включая допустимый TMPDIR) разбивают аргументы, из-за чего smoke test не запускает сервер. Корректно экранировать аргументы unit-файла.  
    **Дополнительный риск:** выбор свободного порта через bind-to-zero с последующим закрытием сокета оставляет race window до запуска сервера.

25. **Серверный provenance не учитывает DTLS-исходник — scripts/server_asset_provenance.ps1.**  
    **Подтверждённый дефект.** Get-BuildInputRecords() включает rust-server/src/**/*.rs и shared/wire_protocol.rs, но пропускает shared/dtls.rs, напрямую подключённый production-сервером. Изменение DTLS не меняет buildInputSha256; Verify может принять бинарник со старой криптографической реализацией. Включить все реально подключаемые исходники.

26. **Клиентский provenance не учитывает реальные build inputs — scripts/native_client_provenance.ps1.**  
    **Подтверждённый дефект.** Хэш включает только корневые rust-client/*.rs, но пропускает rust-client/src/**; из vendored-кода учитывается vendor/primp, но пропускается подключённый через Cargo vendor/netstack-smoltcp. Verify может признать устаревший бинарник актуальным. Рекурсивно включать все фактические исходники и patched dependencies.

27. **Неполная legacy-миграция может терять данные — rust-server/src/config/model.rs.**  
    **Подтверждённый дефект потери данных.** import_legacy_database_rows() пропускает поля sub_uuid, workers, group_id, routing_rule_id, таблицы client_groups и routing_rules, а также ряд новых полей Database. verify_legacy_database_rows() не сверяет их, поэтому импорт может считаться успешным и удалить исходный JSON после неполного переноса. Расширить импорт/верификацию либо сохранять исходник до подтверждения полной миграции.  
    **Риск:** legacy local_proxy.port сужается из u64 до u16 без проверки диапазона.

28. **Неполная публикация артефактов и незавершённые дочерние процессы — rust-server/build_linux_variants.ps1.**  
    **Риски надёжности сборки.** При частичной ошибке скрипт может скопировать успешные архитектуры поверх прежнего набора, оставив смесь старых и новых бинарников. Если запуск очередного процесса выбрасывает исключение, ранее запущенные процессы не завершаются в finally. Следует прекращать дочерние процессы и публиковать набор артефактов атомарно. Также Cargo-команды без --locked могут менять lockfile.

29. **Cargo-команды без --locked — rust-server/build_linux.bat, rust-server/build_linux.sh, rust-server/build_linux_variants.ps1.**  
    **Риск воспроизводимости.** Часть clippy/test/zigbuild-команд выполняется без --locked; Cargo может обновить lockfile в ходе сборки/проверки. Добавить --locked ко всем соответствующим командам.

30. **Runner зависит от предварительной установки cross-targets — rust-server/rust-toolchain.toml / rust-server/build_linux_variants.ps1.**  
    **Рекомендация.** Toolchain по умолчанию содержит только x86_64-unknown-linux-musl; дополнительные targets устанавливаются вызывающими сценариями, но самостоятельный запуск runner зависит от их предварительной подготовки. Документировать предусловие либо проверять/устанавливать targets внутри runner.

## 4. Сложные дефекты: сетевой стек, безопасность, конкурентность и криптография

31. **IPv4-фрагменты обрабатываются как полные пакеты — rust-client/src/transport/relay/direct_relay.rs.**  
    **Подтверждённый дефект.** Проверяется ненулевой fragment offset, но не флаг MF. Первый фрагмент (offset 0, MF 1) попадает в TCP/UDP обработчик как целый пакет, а последующие отклоняются. Отклонять все фрагменты либо выполнять reassembly.

32. **Нарушается flow affinity IPv4-фрагментов — rust-server/src/tun/tun_device.rs.**  
    **Подтверждённый дефект.** Первый фрагмент получает ключ с TCP/UDP портами, последующие — с нулевыми портами; IPv4 Identification не входит в ключ. Фрагменты одной дейтаграммы могут попасть на разные worker, а фрагменты разных дейтаграмм — ошибочно объединиться. Учитывать IPv4 Identification и строить согласованный ключ для всех фрагментов.

33. **Нулевые размеры буферов вызывают panic — rust-client/vendor/netstack-smoltcp/src/stack.rs.**  
    **Подтверждённый дефект устойчивости.** Публичные setters принимают ноль, а build() передаёт его в tokio::sync::mpsc::channel(), который требует ненулевую ёмкость. Возникает panic вместо контролируемой ошибки. Валидировать значения и возвращать InvalidInput.

34. **Один повреждённый UDP-пакет завершает Stream — rust-client/vendor/netstack-smoltcp/src/udp.rs.**  
    **Подтверждённый дефект.** Ошибки разбора IP/UDP преобразуются в None, а для Stream это означает окончательное завершение. Последующие корректные датаграммы перестают читаться, хотя канал остаётся открыт. Пропускать некорректный кадр либо возвращать ошибку без завершения потока.

35. **IPv6 extension headers не обходятся при анализе SNI/DNS — rust-client/src/security/sni.rs.**  
    **Риск неполного анализа пакетов.** IPv6 Next Header трактуется как конечный TCP/UDP протокол; пакеты с extension headers остаются без SNI/DNS-анализа. Также не проверяется минимальный TCP Data Offset, а TLS parser может принять усечённый ClientHello. Нужны корректный разбор extension headers и строгая проверка длин заголовков/record.

36. **Batch-вставка обходит лимит DNS→domain cache — rust-client/src/security/sni.rs.**  
    **Подтверждённый дефект.** insert_multiple() очищает старые записи, но затем вставляет весь batch без повторного ограничения; при max_entries == 0 одиночная и пакетная вставки также могут сохранять записи. Кэш превышает заданный лимит и способен неконтролируемо расходовать память. Ограничивать каждую вставку и размер batch.

37. **Новая передача routing может смешаться с предыдущей — rust-client/src/session/session.rs.**  
    **Подтверждённый дефект.** RoutingReassembler::feed() очищает накопленные chunks при START только если новое число частей отличается от старого. Повторный START с тем же числом частей сохраняет старые фрагменты; результат может содержать смешанные данные. Сбрасывать состояние при каждом START.

38. **Распаковка routing payload не ограничена по размеру — rust-client/src/session/session.rs.**  
    **Риск исчерпания памяти.** assemble() распаковывает gzip через read_to_string() без лимита выходного размера; число chunks не ограничивает суммарный объём или коэффициент распаковки. Ограничить encoded и decompressed payload.

39. **Fast-path TURN отправляет данные во время закрытия — rust-client/src/transport/turn/turn.rs.**  
    **Подтверждённый риск гонки.** try_send_fast(), is_alive() и is_sendable() не учитывают shared.closing. После начала cleanup пакет ещё может быть принят в очередь, хотя writer уже завершился или завершится, и останется неотправленным. Учитывать closing в проверках доступности и отправке.

40. **Очереди логирования гоняются с очисткой файла — rust-server/src/web_panel/monitoring.rs.**  
    **Подтверждённый дефект конкурентности.** logs_clear() очищает in-memory ring и удаляет файл без синхронизации с отдельным writer thread. Уже поставленные в очередь старые записи могут записаться после удаления и заново создать shod.log, хотя API вернул HTTP 200. Выполнять очистку как упорядоченную команду в очереди writer.

41. **Очистка Cache Storage удаляет кэши других приложений — rust-server/src/web_panel/assets/sw.js.**  
    **Подтверждённый дефект изоляции.** При activate service worker удаляет все origin-wide кэши, кроме собственного CACHE_NAME. Cache Storage общий для origin, поэтому могут быть удалены данные других приложений. Ограничить очистку собственным префиксом.

42. **XSS через inline onclick при имени proxy-профиля — rust-server/src/web_panel/assets/panel.html.**  
    **Подтверждённый дефект безопасности.** Имя профиля вставляется в inline JavaScript-атрибут после HTML-экранирования. Браузер декодирует HTML-сущности до разбора JavaScript, поэтому апостроф снова становится разделителем строки. Backend разрешает апостроф. Не помещать пользовательские данные в inline JS; использовать обработчики событий и безопасную передачу данных.

43. **Bearer-токен не маскируется в логах — app/src/main/java/com/shod/client/vpn/diagnostics/NativeTunnelLogParser.kt.**  
    **Подтверждённый дефект безопасности.** Regex для Authorization не учитывает схему Bearer, поэтому Authorization: Bearer abc123 оставляет токен открытым. Маскировать значение заголовка с учётом схемы и добавить тесты Bearer/Basic.

44. **Общие TPROXY status-файлы конфликтуют между экземплярами — rust-server/src/proxy/proxy_route.rs.**  
    **Подтверждённый дефект изоляции процессов.** RUNTIME_COUNTER начинается с 1 в каждом процессе, а путь status/error socket строится только по этому счётчику в общей temp-директории. Второй экземпляр может удалить сокет первого и нарушить status/readiness. Использовать уникальный идентификатор экземпляра и удалять только принадлежащие ему файлы.  
    **Дополнительный риск безопасности:** запись error-файла через предсказуемый путь в /tmp может следовать symlink при локальной гонке. Нужны приватный каталог и безопасное эксклюзивное создание без следования ссылкам.

45. **Per-device quota может вытеснять соединения других клиентов — rust-server/src/proxy/tproxy.rs.**  
    **Подтверждённый дефект изоляции клиентов.** При достижении лимита одного клиента функции eviction выбирают старейшее TCP-соединение/UDP-поток из общей коллекции без фильтра по IP. Один клиент способен вытеснять трафик других, сам не получая новое соединение. При device limit выбирать жертву только среди соединений того же клиента; глобальное вытеснение оставлять для global limit.

46. **DTLS sequence number повторно использует AES-GCM nonce — shared/dtls.rs.**  
    **Подтверждённый критический дефект криптографии.** В RecordProtector::protect() 48-битный sequence number после максимума оборачивается к нулю при том же ключе и fixed IV. Повтор nonce разрушает гарантии AES-GCM. Останавливать отправку/требовать новую эпоху и ключи до переполнения.

47. **DTLS принимает all-zero X25519 shared secret — shared/dtls.rs.**  
    **Подтверждённый критический дефект криптографии.** EphemeralSecret::agree() возвращает результат Diffie–Hellman без проверки all-zero shared secret, хотя RFC 7748 требует отклонять такой результат. Handshake может продолжиться с предсказуемым premaster secret. Проверять и отклонять all-zero результат.

48. **Клиентский DTLS handshake допускает неаутентифицированный сертификат — shared/dtls.rs.**  
    **Подтверждённый критический дефект безопасности.** accept_certificate() сверяет fingerprint только если ранее вызван pin_fingerprint(). Без pin принимается любой P-256 сертификат, а подпись проверяется ключом из того же непроверенного сертификата; возможен MITM с самоподписанным сертификатом. Требовать ожидаемый fingerprint до handshake либо fail closed.
